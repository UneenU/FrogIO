# FROG.IO — новый рендер матча

## Запуск

`npm ci`, скопировать `.env.example` в `.env`, затем `npm run dev`.
`npm run build` собирает готовый клиент в dist; `npm run preview` запускает сборку.
Нужен прежний backend. JSON остаётся протоколом SignalR по умолчанию; MessagePack включается только явно.

## Что заменено

Удалена вся прежняя папка src/game, включая renderer, camera, input, loader, sheetLayout, sprites, sky, platform, pondFloor, lighting, waterfallSprites, effects, coreEnums, insects, все layers и tongue-kinds. Вместо неё добавлена новая реализация: art.ts, viewport.ts, controls.ts, scene.ts, renderer.ts и новый предпросмотр/галерея. MatchView.vue также удалён и создан заново с новым игровым экраном, управлением, очками, эффектами и выбором улучшений.

- Серверный FrogInfo.radius задаёт базовый радиус тела. Визуальный радиус всех объектов — `radius * (1 + height / 100)`; серверная физика не меняется. В подготовленных кадрах известен радиус тела и центр привязки; лапы могут выходить за круг тела. При улучшении Radius изображение следует серверному значению.
- Кадры выделены по реальным областям непрозрачных рисунков, а не равномерной сетке: для каждого исходника находились фактические промежутки между соседними силуэтами. У ястреба и светлячка сохранены полные крылья без частей соседних спрайтов. Муха 4×2 преобразована в последовательность из восьми изолированных кадров.
- Каждый кадр лягушки привязан к телу. В плавании вытянутые задние ноги исключены из расчёта центра тела. Цветовые варианты проходят одинаковые преобразования и имеют побайтно одинаковую геометрию альфа-канала.
- Исходные PNG пользователя сохранены в src/assets/game. Подготовленные для рендера кадры и тени находятся в src/assets/match. Никаких новых рисунков или SVG-замен нет.
- Во время матча отсутствуют getImageData, нарезка, масштабирование исходных лент во временные холсты, фильтры blur и генерация теней. Тени птицы подготовлены заранее. Суммарная распакованная память игровых спрайтов около 43 MiB.
- Один requestAnimationFrame и один таймер ввода 15 Гц на матч. При уходе со страницы они удаляются; в скрытой вкладке рендер приостанавливается. DPR ограничен 1.5, буфер — примерно 2 миллионами пикселей. Объекты за экраном отбрасываются.
- Движение лягушек и насекомых сглаживается между снимками. Птица рисуется строго в координатах текущего серверного состояния; её модель и тень используют один кадр. Привязка кадров ястреба выполняется по клюву с постоянным смещением к телу, а не по меняющимся границам крыльев. При загрузке ленты разделяются на отдельные изображения кадров, чтобы исключить выборку соседних спрайтов при повороте и увеличении.
- Вернулись водопады по четырём краям, вид строго сверху, и небольшое визуальное скругление платформы. Водопады используют одну маленькую повторяемую текстуру; серверные границы остаются прямоугольными.
- Кувшинка под курсором подсвечивается по визуальному радиусу. Освещение плавно следует worldHour из состояния матча, включая переход 23 → 0, без порогового переключения палитры.
- Эффект-цвет задан в src/game/effectColors.ts: ускорение — оранжевый, опыт — фиолетовый, неизвестный эффект — белый. Окружности насекомых заменены мягким круглым свечением. Светлячок всегда имеет дополнительный жёлтый ореол.

## Проверка

TypeScript и production-сборка проходят. Выполнена отрисовка production-кода через Skia и проверка всех кадров ястреба/светлячка на обрезание по границам ячеек; проверено совпадение геометрии трёх цветов лягушки. Контрольные изображения приложены отдельно. Синтетический прогон: 100 лягушек и 400 насекомых при 1440×861; результат в match-render-check.json рядом с архивом. Это программный Canvas/Skia-тест, не измерение FPS в браузере пользователя и не проверка сетевого матча с backend.

`/visual-preview.html` показывает реальные подготовленные кадры; красный круг в галерее — хитбокс тела. Добавление `?hitboxes` к URL матча включает круги для всех лягушек.

## Обновление ассетов

Готовые кадры уже включены, Python для запуска/сборки клиента не нужен. Для повторной подготовки после изменения исходников: `npm run assets:generate` создаёт цветовые варианты; `npm run assets:prepare` заново готовит кадры (для этого инструмента нужны Python, Pillow, numpy, scipy). Размеры и точка привязки записываются в manifest.json.

В архиве исходники и dist, без node_modules и личного .env.
