# FrogIO

Многопользовательская игра про лягушек.

- `Core/` — игровая симуляция и механики.
- `Server/` — ASP.NET Core API, SignalR, авторизация и хранение результатов.
- `Client/` — клиент на Vue, TypeScript и Vite.
- `Caddyfile` — HTTPS, раздача клиента и проксирование API и SignalR.
- `compose.yaml` — запуск приложения, PostgreSQL, Redis и миграций.

**Запуск через Docker**

Команды выполняются из корня репозитория.

1. При первом запуске скопировать `.env.example` в `.env`. В PowerShell:

   ```powershell
   Copy-Item .env.example .env
   ```

   На Linux:

   ```bash
   cp .env.example .env
   ```

   Если `.env` уже существует, отредактировать его, сохранив действующие параметры подключения.

2. Заполнить `.env`:

   - `SITE_ADDRESS` — имя сайта или IP без протокола, порта и завершающего `/`. Для локального запуска — `localhost`.
   - `WEB_BIND_ADDRESS` — `127.0.0.1` для доступа с этого компьютера, `0.0.0.0` для доступа через сетевые интерфейсы.
   - `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` — параметры PostgreSQL.
   - `DOCKER_SUBNET`, `PROXY_IP` — внутренняя подсеть контейнеров и адрес Caddy. Значения из примера можно использовать, если подсеть не пересекается с другими сетями.

3. Проверить конфигурацию и запустить проект:

   ```bash
   docker compose config --quiet
   docker compose up -d --build
   ```

4. Открыть `https://localhost` или `https://<SITE_ADDRESS>`.

При первом запуске PostgreSQL создаёт базу, а одноразовый сервис `migrate` применяет миграции EF Core. Его нормальное состояние после выполнения — `Exited (0)`. Игровой сервер запускается после успешных миграций.

**Локальный HTTPS**

Текущий `Caddyfile` использует `tls internal`. Для доверия к сертификатам установите публичный корневой сертификат своего Caddy на устройства, с которых открывается игра.

На Windows, в PowerShell:

```powershell
docker compose cp web:/data/caddy/pki/authorities/local/root.crt "$env:TEMP\frogio-local-root.crt"
certutil -user -addstore Root "$env:TEMP\frogio-local-root.crt"
```

Вторая команда добавляет локальный центр сертификации Caddy в доверенные для текущего пользователя.

Для доступа из домашней сети задайте локальный IP компьютера в `SITE_ADDRESS`, используйте `WEB_BIND_ADDRESS=0.0.0.0` и разрешите входящие TCP-подключения к портам 80/443 из локальной сети в брандмауэре.

**Команды обслуживания**

```bash
# Состояние всех сервисов, включая завершившийся мигратор
docker compose ps -a

# Последние сообщения игрового сервера
docker compose logs --tail=100 server

# Логи всех сервисов в реальном времени
docker compose logs -f

# Обновление приложения с остановкой игры на время миграций
docker compose stop web server
docker compose up -d --build

# Остановка сервисов
docker compose stop
```

Обновление игрового сервера прерывает активные матчи.

**Данные и локальные настройки**

PostgreSQL хранит пользователей, рейтинг и историю в volume `postgres_data`. Ключи аутентификации сохраняются в `server_keys`, сертификаты и состояние Caddy — в `caddy_data` и `caddy_config`.

Redis настроен на работу без сохранения на диск. При его перезапуске теряются временные записи о лобби, соединениях и привязках к матчам.

Команда `docker compose down` удаляет контейнеры и сеть, сохраняя volumes. Флаг `-v` удаляет управляемые Compose volumes, включая данные БД и ключи. Перед изменением схемы или переносом базы делайте резервную копию.

**Публичное развёртывание**

Для публичного домена укажите его в `SITE_ADDRESS`, задайте `WEB_BIND_ADDRESS=0.0.0.0` и уберите `tls internal` из `Caddyfile`. DNS домена должен указывать на сервер, а TCP-порты 80/443 должны быть доступны извне. Caddy сможет получить и обновлять публичный сертификат автоматически.
